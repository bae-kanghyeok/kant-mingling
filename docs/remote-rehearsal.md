# 외부 링크로 혼자 리허설하기

이 문서는 **개발 DB의 합성 행사**를 외부 Preview에서 혼자 확인하는 감독 리허설 안내다. 실제 게임 화면과 서버 동작을 사용하며, 감독이 필요한 순간에 참가자 역할을 바꾸고 다른 합성 참가자의 응답을 한 번씩 진행한다.

> 현재는 구현·배포 검증 중인 안내 초안이다. 아래 절차를 작성했다고 실제 외부 리허설이 검증된 것은 아니다. 검증 상태는 문서 마지막 표를 따른다.

## 검토자에게 전달할 것

- 담당자가 준비한 **`/rehearsal/<slug>` 경로까지 포함된 Preview 링크**.
- 감독을 시작할 **호스트 운영진 이름과 해당 행사 코드**. 코드는 링크·문서·저장소에 함께 게시하지 않고 별도로 전달한다.
- 이 행사는 가상 이름과 합성 응답을 사용하며 실제 행사 결과를 변경하지 않는다는 설명.

개발 DB에는 학생 18명과 운영진 3명의 프로필이 준비돼 있다. 표시되는 온라인 인원은 실제로 화면을 확인하는 세션 기준이므로 전원이 온라인으로 보일 필요는 없다.

## 처음 들어가기

1. 전달받은 리허설 링크를 연다.
2. 호스트 운영진 코드를 입력하고 **호스트로 로그인 · 리허설 켜기**를 누른다. 코드는 한 번 입력한다.
3. **온라인 합성 리허설 · 실제 DB로 진행** 표시와 호스트 게임 화면을 확인한다.
4. 아직 시작 전이라면 관리자에서 **조 편성 → 조 배정 공개 → Game 1 전체 시작**을 진행한다. 이미 첫 게임이 준비돼 있다면 바로 역할을 선택한다.

감독을 시작한 뒤에는 같은 창 안에서 합성 참가자의 화면을 바꿔 본다. 여러 탭에 21명의 화면을 열 필요가 없다. 참가자 화면의 버튼은 실제 게임 명령이므로, 추리·게임 종료·행사 종료를 누르면 합성 행사의 진행도 실제로 바뀐다.

## 화면을 바꾸며 확인하기

| 확인할 것 | 진행 방법 |
| --- | --- |
| 학생 화면 | **참가자 역할**에서 학생을 고르고 **선택한 역할로 전환**해 받은 Data와 사용 가능한 버튼을 확인한다. |
| 수신·비수신 차이 | 같은 조의 Data 수신자와 다른 학생 화면을 번갈아 본다. 수신자에게 질문 원문과 선택 답변이 보이고, 다른 사람에게는 받은 사람만 보여야 한다. |
| 다음 단서·추리 | 현재 Turn Lead 역할로 이동해 팀 대화를 가정한 뒤 다음 Data 또는 추리를 선택한다. |
| Noise 안내 | 안내를 읽고 확인한다. 공개 전에는 어느 카드가 Noise인지 보여주지 않는다. |
| Ensemble 공유 | 공유자 역할에서 받은 단서를 확인하고 **공유했어요**를 누른다. |
| 다른 참가자 응답 | **다른 참가자 데모 응답**을 한 번 누른다. 현재 선택한 참가자의 조에 적용된다. 실행 결과를 확인한 뒤 필요한 다음 단계는 직접 진행한다. |
| 투표·결과·토론 | 현재 선택한 사람의 표를 직접 고르고, 마감 뒤 결과를 본다. 이유를 이야기하는 단계를 확인한 뒤 **토론 마침**으로 이어간다. |
| Ground Truth | 실제 카드 안내를 확인한다. 처음에는 설명이, 이후에는 간단한 확인 안내가 나오는지 본다. |
| 정답 공개 | 정답과 Noise의 실제 답, Behind the Data 질문을 확인한다. |
| 호스트 관제 | **호스트로 돌아가기** 뒤 관리자에서 A/B/C조의 단계·연결 상태·복구 기능을 확인한다. |

역할을 바꾼다고 모든 단서나 정답을 한꺼번에 보여주지는 않는다. 선택한 참가자가 실제로 받을 수 있는 데이터만 보이고, 호스트·감독도 공개 전 정답을 받지 않는다.

**다른 참가자 데모 응답**은 현재 조에서 보고 있지 않은 합성 참가자의 안내 확인과 Ensemble 공유·투표·토론 마침을 **누른 시점에 한 번** 보조한다. 공유자나 토론 진행자가 현재 선택한 역할이면 게임 화면에서 직접 누른다. 다른 사람의 투표는 정답과 무관한 데모 선택이다. 게임의 다음 단서·추리·다음 게임·자리 이동은 직접 진행한다. 한 번에 한 단계를 보조하므로 공유 뒤 투표나 투표 마감 뒤 토론으로 단계가 바뀌면 필요할 때 다시 누른다.

화면이 이전 상태에 머물면 **상태 새로고침**, 게임 화면을 다시 불러오려면 **게임 화면 다시 열기**를 사용한다. 잠시 검토를 멈출 때는 **게임 화면 잠시 닫기**로 현재 게임의 반복 조회를 멈춘다. 감독 화면은 자동으로 21명의 화면을 조회하지 않는다.

## 다음 게임과 자리 이동

정답을 공개한 뒤 운영진 역할에서 다음 Game을 시작한다. 한 조의 진행은 다른 조와 독립적이다. 빠르게 운영 흐름을 보려면 호스트 관제에서 조를 선택하고 **현재 Game 종료 → 다음 Game**을 사용한다.

A/B/C조가 모두 Game 3을 마치면 호스트가 **다음 블록 시작**으로 새 조를 공개한다. 각 조에서 **착석 완료 · Game 시작**을 진행해 다음 블록을 시작한다. Game 6 뒤에도 같은 흐름을 확인한다. 참고 타이머는 게임을 자동 종료하지 않는다.

Game 9를 모두 마치면 마지막 대화 안내를 확인한다. **전체 종료는 모든 확인이 끝난 뒤 마지막에 실행한다.** 끝난 행사는 새 참가자가 입장할 수 없고, 처음부터 다시 보려면 담당자가 새 합성 행사를 준비해야 한다.

검토를 마치면 **리허설 감독 종료**를 누르고 창을 닫는다. 감독 종료는 현재 감독과 선택한 역할의 세션을 회수하고 합성 게임 데이터는 유지한다. 이전 역할의 세션은 역할을 바꿀 때 회수한다. 창만 닫으면 즉시 세션 회수되지는 않고 최대 2시간의 감독 만료가 적용된다. 게임 일시정지만으로 브라우저의 상태 조회가 멈추지는 않는다.

이 감독 리허설의 합성 명단은 고정이다. 관제에서 이름·역할·활성 여부를 바꾸거나 참가자를 추가하면 감독 기능이 차단된다. 인원 가변·명단 변경 검증은 감독 모드를 사용하지 않는 별도 개발 행사에서 진행한다. 호스트 변경이나 코드 재발급을 검토했다면 새 호스트 코드로 다시 로그인해야 한다. 전체 종료 후에는 새 감독 로그인이 불가능하므로 결과 확인까지 마친 뒤 종료한다.

## 담당자 준비

### 합성 행사와 계정

일반 설치와 환경 구분은 [설치 안내](install-human.md)를 따른다. 외부 리허설에는 개발 DB만 사용하고, Vercel Preview가 같은 개발 DB와 `AUTH_SECRET`을 사용해야 한다. 먼저 해당 계정의 DB 전송량·가용 상태를 확인한다.

```text
node scripts/mark-environment.mjs development
npm run migrate
node scripts/seed-dev-event.mjs --quiet
node scripts/prepare-dev-rehearsal.mjs --slug <생성된-dev-slug> --synthetic
```

이 경로는 합성 명단·프로필을 준비하고 21개 브라우저 세션이나 계속 실행되는 봇을 만들지 않는다. `seed-dev-event`의 호스트는 운영진A다. 검토 담당자가 사용할 코드는 필요한 운영진에 한해 별도로 발급한다. 코드를 다시 발급하면 해당 운영진의 이전 로그인 세션이 해제된다.

```text
node scripts/issue-operator-codes.mjs --slug <생성된-dev-slug> --name 운영진A --synthetic
```

코드 발급 출력은 담당자의 터미널에서 수령하고 채팅·CI 로그·공개 문서에 보관하지 않는다. 입력 화면 자체를 검토할 때는 프로필을 채우지 않은 별도 합성 행사를 준비하면 된다.

### 리허설 기능의 환경 계약

다음은 구현 담당자 간 확정한 계약이며, 실제 배포 검증은 아래 체크리스트에서 별도로 기록한다.

| 설정·조건 | 값 또는 동작 |
| --- | --- |
| `REHEARSAL_ENABLED` | 외부 리허설용 Preview에만 `true`를 지정. 기본 비활성 |
| `REHEARSAL_EVENT_SLUG` | 준비한 `dev-...` 합성 행사 하나를 정확히 지정 |
| `DEVELOPMENT_NEON_ENDPOINT` | 별도로 확인한 새 개발 DB endpoint ID |
| `DATABASE_URL` | 위 개발 endpoint와 일치하는 연결. DB 표지도 `development`여야 함 |
| `AUTH_SECRET` | 일반 앱과 동일한 해당 개발 환경의 비밀값 |
| Production | `VERCEL_ENV=production`이면 활성화 값이 있어도 감독 API는 404 |
| 명단 | 학생01~18·운영진A~C의 합성 21명만 사용 |
| 감독 진입 | 입력한 코드를 기존 호스트 인증 절차로 확인하고 별도 HttpOnly 감독 쿠키 발급. 기존 학생 화면으로 로그인돼 있어도 호스트 코드로 다시 진입 가능 |
| 감독 유효기간 | 최대 2시간, 원래 호스트 세션 만료 시점 이내 |
| 선택한 역할 세션 | 감독 유효기간을 넘겨 발급하지 않음 |
| 감독 종료 | 원래 호스트 세션과 현재 선택한 역할 세션 회수, 감독·게임 쿠키 삭제, 게임 데이터 유지 |
| 요청별 검사 | 현재 호스트·활성 상태·코드 해시·호스트 세션 만료 및 회수 여부 재검증 |
| API | `GET /api/rehearsal`, `POST /api/rehearsal`. 쿠키·코드는 URL에 넣지 않음 |
| 역할 전환 | 같은 합성 행사 참가자만 선택. 감독 권한을 서버에서 확인하고 이전 비호스트 역할 세션 회수 |
| 수동 보조 | 현재 선택한 역할의 조에만 적용. 다른 합성 참가자 안내 확인·Ensemble 공유·투표·토론 마침을 기존 게임 명령으로 실행. 정답을 읽고 고르지 않음 |

Vercel 환경변수를 변경하면 새 Preview를 배포한다. 다른 Preview에서 함께 사용할 필요가 없으면 해당 배포 브랜치 범위로 제한한다. 코드 재발급·호스트 변경·원래 호스트 세션 해제는 감독 권한에도 영향을 주므로 검토 중에는 대상과 영향을 확인한다.

일반 행사 인증 경로나 Production을 감독 모드로 바꾸지 않는다. 원래 로컬 전용인 `scripts/rehearsal.mjs` 프록시를 외부로 공개하거나, 쿠키·운영진 코드·정답을 URL에 넣어서 역할 전환을 구현하지 않는다.

## 검증 기록과 체크리스트

기존 UI 개편 검증에서는 lint·TypeScript·단위 테스트 57개·콘텐츠 검사·Production 빌드가 통과했고, Production에서 `/design-preview`가 404로 차단된 것을 확인했다. 이는 **이번 외부 감독 리허설의 검증 결과가 아니다.** 당시 실제 DB 재검증은 사용량 제한으로 진행하지 못했다. 범위는 [UI 검토 기록](ui-review.md)에 남아 있다.

이번 감독 기능은 코드 검토에서 환경·명단·호스트 권한 검사, 역할 세션 회수, 단일 게임 화면 연결, 수동 보조의 적용 범위를 확인했다. 구현 담당자는 전용 단위 테스트 6개와 TypeScript·대상 파일 ESLint 통과를 보고했다. DB 통합 테스트와 외부 브라우저 검증은 별도다.

아래 항목은 실제 수행한 뒤 결과·commit·배포 환경을 기록한다. 현재 `미검증`은 테스트를 완료했다는 뜻이 아니다.
