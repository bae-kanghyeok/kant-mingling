# 게임과 기술 개요

## 참가 흐름

`/e/<slug>` 접속 → 명단에서 본인 이름 선택 → 운영진만 코드 인증 → A/B 20문항 작성 → 조 배정 → 조별 게임 → 정답 공개 후 대화 → 블록 종료와 자리 이동 → 마지막 대화와 호스트 전체 종료.

3블록, 블록당 3게임을 사용한다. 조별 진행은 독립적이다. 참고 타이머는 자동으로 게임을 종료하지 않는다. 호스트가 전체 운영을 통제하고 각 조 운영진은 담당 조를 제어한다.

Data Owner는 서버가 고른다. Data를 받은 사람은 팀원에게 내용을 말로 공유하고 마지막 수신자인 Turn Lead가 다음 단서 또는 추리를 선택한다. Noise는 실제 선택의 반대 답이다. Ensemble에서는 공유·개별 투표·토론이 진행되고 Ground Truth는 실제 단서 하나를 확인한다. 정답 뒤에는 Behind the Data 질문으로 대화를 이어간다.

## 구조

| 경로 | 책임 |
| --- | --- |
| src/components | 입장·프로필·게임·관리자 화면과 상태 조회 |
| src/app/api | 인증된 API 진입점과 입력 검증 |
| src/server/game | DB와 분리된 규칙·배정·이동 계산 |
| src/server/services | 트랜잭션 안에서 게임·관리 명령 수행 |
| src/server/dto | 역할·수신 여부에 따른 응답 허용 목록 |
| src/server/auth | 쿠키 세션, 운영진 코드, 호출 제한 |
| db/migrations | 스키마와 체크섬 기반 migration |
| scripts | 설치·명단·개발 DB 테스트·로컬 리허설 |
| tests | 게임 단위 검증과 실제 개발 DB 통합 검증 |

Next App Router와 짧은 폴링을 사용한다. API 명령 뒤에 상태를 다시 조회한다. 세션은 DB에서 복구하고 버전·requestId로 충돌과 중복 명령을 처리한다. DB 잠금을 잡은 상태에서 외부 API를 호출하지 않는다.

## 공개 전 데이터 경계

정답 ID, 실제/Noise 구분, 원래 답, Noise 배치, 난수 seed와 추리 내부 지표는 서버 전용이다. 운영진·호스트 응답도 이 경계를 따른다. 카드의 질문 원문과 표시 답은 수신자에게만 보내고, 정답 공개 후 해당 게임 참가자에게 공개한다. 클라이언트 CSS로 숨기는 방식은 사용하지 않는다.

프로필은 취향과 대화를 위한 정보다. 심리 진단·성격 유형·점수·순위 기능은 없다. 실제 참가자의 이름·답변·운영진 코드는 공개 저장소에 포함하지 않는다.

## 환경과 검증

앱은 pooled DATABASE_URL을 사용한다. migration은 직접 연결 DATABASE_URL_UNPOOLED을 사용한다. 운영 스크립트는 연결 endpoint, DB 환경 표지, 명시적인 운영 인자를 함께 검사한다. 환경 표지를 바꿔 검사를 우회하면 안 된다.

48개의 기존 단위 테스트에 새 설치 환경의 endpoint 검사를 보강했다. 자동 테스트 수와 최근 결과는 커밋·CI 결과에서 확인한다. 실제 기기 리허설과 큰 행사 규모의 부하 검증은 별도 작업이다.
