# 21명이 모두 참여한 상태로 플레이하기

한 브라우저에서 학생·운영진 화면을 오가며 실제 게임과 관제를 체험하는 **현재 PC 전용 리허설**입니다. 다른 브라우저나 21개의 브라우저 프로필을 준비할 필요가 없습니다.

## 시작

프로젝트 폴더에서 실행합니다. 기존 개발 DB 연결 설정과 Node.js 24가 준비되어 있어야 합니다.

```powershell
npm run rehearsal
```

빌드와 가상 행사 준비가 끝나면 [http://127.0.0.1:3100](http://127.0.0.1:3100)을 엽니다. **주소를 `localhost`로 바꾸지 마세요.** 리허설은 지정한 주소만 허용합니다. 이 주소는 실행한 PC에서만 열리며, 다른 사람이나 휴대폰에 공유하는 행사 링크가 아닙니다.

시작할 때 다음 상태가 준비됩니다.

- 학생01~18과 운영진A~C, 총 21명의 가상 참가자
- 전원 20문항 프로필 작성 완료와 참가 세션
- A·B·C조 배정 완료, 각 조 Game 1 시작
- 처음 표시되는 화면은 호스트인 운영진A의 실제 게임 화면

새 개발 행사에 합성 답변을 넣습니다. 기존 Preview 행사와 운영 배포는 변경하지 않습니다. 참가자 화면은 기존 앱의 UI·API·권한·게임 규칙을 그대로 사용하며, 리허설을 위해 앱 핵심 소스를 변경하지 않았습니다.

## 화면을 오가며 플레이하기

| 컨트롤러 버튼 | 사용법 |
| --- | --- |
| 학생·운영진 이름 | 해당 사람의 실제 화면을 엽니다. 그 사람에게 전달된 Data와 허용된 동작이 표시됩니다. |
| 진행권자 화면 | 해당 조의 현재 Turn Lead 화면으로 이동합니다. |
| 진행권 자동 따라가기 | 선택한 조의 Turn Lead가 바뀌면 그 사람의 화면으로 자동 이동합니다. 다른 이름을 직접 누르면 따라가기가 해제됩니다. |
| 공유자 화면 | Ensemble에서 단서를 공유할 사람의 화면으로 이동합니다. |
| 호스트 관제 | 운영진A 화면을 엽니다. 그 안의 오른쪽 위 **관리자** 버튼을 눌러 관제 패널을 엽니다. |
| 새 탭에서 열기 | 선택한 참가자 화면을 별도 탭으로 엽니다. 컨트롤러는 원래 탭에 남습니다. |
| 새 리허설 | 새 가상 행사를 준비하고 Game 1부터 다시 시작합니다. |

첫 체험은 한 조의 **진행권자 화면**으로 이동한 뒤 **진행권 자동 따라가기**를 켜면 편합니다. Data를 확인하고 **Data 하나 더 보기**나 **추리하기**를 눌러봅니다. 다른 이름을 선택하면 Data가 수신자에게만 보이는 것도 확인할 수 있습니다.

Ensemble의 공유 단계에서는 **공유자 화면 → 공유했어요**를 누릅니다. 현재 보고 있는 사람의 투표를 직접 고르고, 투표가 끝나면 결과와 토론 단계를 확인합니다. **토론 마침**은 공유자나 운영진 화면에서 진행할 수 있습니다.

정답이 공개되면 Behind the Data를 확인하고, 해당 조 운영진 화면에서 다음 Game을 시작합니다. 정답 공개 흐름을 바로 확인하려면 호스트의 관리자 패널에서 조를 고른 뒤 **현재 Game 종료**를 실행할 수도 있습니다.

## 가상 참가자가 자동으로 하는 일

**가상 참가자 자동 응답**은 기본으로 켜져 있습니다. 컨트롤러에서 선택한 사람을 제외한 참가자들의 규칙 안내 확인과 Ensemble 투표만 처리합니다. 가상 투표는 공개된 후보 목록으로 선택하며, 숨겨진 정답을 조회하지 않습니다. 이미 제출된 투표를 덮어쓰지도 않습니다.

현재 선택한 사람의 안내 확인·투표는 직접 진행합니다. **단서 요청, 공유 완료, 추리, 토론 종료, 다음 Game, 자리 이동 같은 운영 명령도 직접 진행합니다.** 세 조의 게임이 자동으로 끝나거나 다음 판으로 넘어가지는 않습니다.

컨트롤러 탭은 하나를 기준으로 사용합니다. 여러 컨트롤러를 열면 선택한 참가자가 공유되어 서로 화면 전환에 영향을 줄 수 있습니다. 비교 화면은 **새 탭에서 열기**로 참가자 화면을 엽니다.

참가자들의 접속 상태는 리허설이 사용되는 동안 유지됩니다. 컨트롤러와 참가자 화면을 모두 닫거나 백그라운드에 둬 요청이 30초 이상 없으면 가상 참가자의 폴링도 멈춥니다. 화면으로 돌아오면 다시 이어집니다. 별도 탭에서도 계속 플레이할 수 있지만, 자동 응답에서 제외되는 사람은 컨트롤러에서 선택한 한 명입니다.

## 관제와 자리 이동 확인

**호스트 관제 → 관리자**에서 A·B·C조를 골라 일시정지·재개, Data 재전송, Turn Lead 변경, 현재 Game 종료, 다음 Game 등을 확인합니다. 공개 전 정답은 관리자에게도 표시되지 않습니다.

자리 이동까지 보려면 세 조가 모두 Game 3을 마쳐야 합니다. 호스트가 **다음 블록 시작**으로 새 조를 공개한 뒤, 각 조의 **착석 완료 · Game 시작**을 진행합니다. Game 6을 마친 뒤에도 같은 흐름을 확인할 수 있습니다. 각 조를 직접 진행하거나, 관제의 현재 Game 종료·다음 Game을 이용해 이동 단계까지 갈 수 있습니다.

이 환경은 시작할 때 만든 21명의 이름과 세션을 기준으로 화면 버튼과 가상 참가자를 연결합니다. **이름 변경·참가 등록 해제·잠금 해제·명단 변경**을 시험하면 이 연결이 맞지 않아 일부 화면 전환이나 자동 응답이 멈출 수 있습니다. 특히 운영진은 사전 연결된 합성 세션을 사용하므로, 잠금 해제 후 다시 입력할 운영진 코드가 제공되지 않습니다. 이런 경우 **새 리허설**로 다시 준비하세요.

## 종료와 다시 시작

화면의 **새 리허설**은 이전 합성 행사 기록을 보존하고 별도의 새 행사를 만듭니다. 실행 중인 명령을 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다. 리허설 서버와 자체 앱 프로세스를 종료하고, 이 실행에서 만든 행사들의 세션을 폐기합니다. DB 연결 실패 등으로 세션 정리에 실패하면 세션 만료 시간이 적용됩니다. 합성 게임 기록은 개발 DB에 남습니다.

다시 사용할 때는 `npm run rehearsal`을 실행하고 같은 [컨트롤러 주소](http://127.0.0.1:3100)를 엽니다. 새 행사로 시작하므로 이전 참가자 탭 대신 컨트롤러에서 다시 화면을 선택합니다.

포트 `3002`, `3100~3121`이 이미 사용 중이면 시작하지 않습니다. 기존 서비스를 자동 종료하지 않으므로, 먼저 이 리허설을 실행한 터미널이 남아 있는지 확인합니다. 일반 개발 서버의 `3000` 포트는 별도로 유지됩니다.
