# 사람이 참여하는 GM 리허설 · 4~6명

GM 1명도 플레이어로 참여하는 한 조 리허설이다. **진행자가 대화 뒤 다음 단서나 추리를 열어주는 흐름**을 확인한다. 같은 GM 행사 URL을 전원에게 전달하고, 각자 휴대폰이나 독립 브라우저 세션으로 입장한다.

> 대상은 `gameplayMode: "gm"`으로 만든 새 행사다. 기존 classic 링크나 혼자 역할을 바꾸는 감독 리허설을 새 GM 게임으로 착각하지 않는다. 최신 접속 주소와 호스트 코드 수령 방법은 담당자가 별도로 전달한다. 이 공개 안내에는 실제 명단·코드를 싣지 않는다.

## 1. 인원과 이름 정하기

| 실제 인원 | 6자리 합성 명단에서 사용할 이름 | 시작 전에 할 일 |
| --- | --- | --- |
| 4명 | 운영진A + 학생01~03 | 학생04·05를 결석 처리 |
| 5명 | 운영진A + 학생01~04 | 학생05를 결석 처리 |
| 6명 | 운영진A + 학생01~05 | 전원 참석 확인 |

‘운영진A’가 이 리허설의 조 GM과 총괄 GM을 겸한다. 숫자는 GM을 포함한 총인원이다. 합성 이름은 테스트용 자리 이름이며 실제 행사 명단과 다르다. 5명 안내는 인원 계산 규칙에 따른 경로이므로 별도 실플레이 검증 여부는 완료 기록을 확인한다.

한 사람에게 이름 하나를 정한다. 같은 브라우저의 일반 탭 여러 개는 같은 참가자 세션을 공유하므로 여러 사람처럼 사용하지 않는다. 이전 참가 이름을 바꿔가며 테스트할 때는 GM의 잠금 해제 등 정식 복구 절차를 사용한다.

## 2. 입장과 첫 시작

1. 담당자가 **최신 GM 참가 링크**와 각자의 합성 이름을 전달한다.
2. GM은 별도 안내된 코드 발급 절차로 자기 코드를 수령한다. 코드는 참가자 링크와 함께 단체 공유하지 않는다. 재발급하면 기존 운영진 세션이 해제될 수 있으므로 매번 실행하지 않는다.
3. 각자 이름을 선택해 들어간다. 운영진A만 코드를 입력한다. 튜토리얼은 이전·다음 버튼으로 직접 넘긴다.
4. **GM을 포함한 전원**이 A/B 20문항을 작성하고 제출한다. 실제 사람 리허설에서는 미리 자동 입력한 프로필을 사용하지 않는다.
5. GM이 관제의 참가자 목록에서 실제 참석자를 확인하고 미참여자를 결석 처리한다. 4명이면 학생04·05를 반드시 결석으로 표시한다.
6. **조 편성 → 조 배정 공개 → Game 1 전체 시작** 순서로 진행한다. 제출을 마치지 않은 사람을 놓친 채 강제 시작하지 않는다.
7. 첫 판에 실제 참석자 전원이 후보로 보이는지 확인한다. GM도 후보이며 투표한다.

첫 판은 Noise 0개, Ground Truth 끔이다. 첫 시작만 총괄이 한 번에 열고, 그다음 판부터 조 GM이 설정을 확인해 시작한다.

## 3. GM이 진행할 한 판

시작 멘트:

> 우리 조 안에 숨어 있는 ‘취향의 주인공’을 찾아볼 거예요. 단서가 나오면 여러분도 어느 쪽인지 고르고 이유를 이야기해주세요. 이야기를 나눈 뒤 지금 추리할지, 단서를 더 볼지 함께 정해보겠습니다. 내 답인 것 같아도 정체는 공개할 때까지 잠깐 참아주세요!

| 단계 | 참가자 | GM |
| --- | --- | --- |
| 단서 확인 | 받은 사람이 질문 두 선택지와 표시 답을 읽는다 | “여러분은 어느 쪽이에요?”로 대화를 연다 |
| 대화 | 자기 선택·이유·경험을 나눈다 | 후보에서 제외된 사람도 이야기할 수 있게 묻는다 |
| 다음 행동 | 지금 추리할지, 단서를 더 볼지 의견을 낸다 | **다음 단서** 또는 **추리 열기**를 누른다 |
| 추리 | 현재 추리 담당자가 Owner·필요한 Noise를 골라 제출한다 | 제출을 대신하지 않고 결과를 기다린다. GM 자신이 담당이면 직접 제출한다 |
| 오답 | 새 단서를 기다리며 이야기를 이어간다 | 다음 단서를 전달한 뒤 다시 추리를 연다 |
| 정답 공개 | 어떤 단서에서 알았는지, 실제 선택 이유를 나눈다 | 후속 대화를 진행하고 다음 판을 준비한다 |

첫 판은 단서 1개, 이후 판은 3개부터 추리를 열 수 있다. GM이 추리를 열기 전 학생 화면이 기다림 상태인 것은 정상이다. 추리를 열었다가 대화를 더 하기로 했으면 **추리 닫고 대화하기**를 누른다.

오답 뒤에는 추리 허가가 닫힌다. 단서 20개를 모두 보기 전까지는 새 단서가 필요하며, 20개를 다 봤으면 GM이 다시 추리를 열 수 있다. 새로고침해도 서버의 상태가 복원되어야 한다.

## 4. Ensemble 투표에서 놓치기 쉬운 점

1. 지정된 사람이 단서를 읽고 함께 이야기한다.
2. GM이 **공유 마침 · 투표 시작**을 눌러 30초 투표를 연다.
3. **GM도 자기 표를 제출한다.** 관제 리모컨이 열린 상태라면 **내 투표 화면으로**를 눌러 닫고 참가자 화면에서 투표한다.
4. 전원 자기 화면에서 투표한다. 다른 사람의 개별 표를 대신 제출하지 않는다.
5. 집계 뒤 이유를 함께 이야기하고, GM이 **토론 마침 · 대화로 돌아가기**를 누른다.

투표가 끝났다고 바로 추리가 열리지는 않는다. 다시 대화를 나눈 뒤 GM이 다음 단서나 추리를 선택한다.

## 5. 다음 판과 자리 이동

정답 공개 후 대화를 마치면 GM이 다음 판의 **Noise 최대 개수 0~5**와 **확실한 단서·Ground Truth 사용 여부**를 고르고 시작한다. 기본은 Noise 최대 1개·Ground Truth 끔이다. Noise를 2개로 설정했더라도 그 전에 정답을 맞히면 끝난다. 일부러 최대 개수가 다 나올 때까지 판을 늘리지 않는다.

같은 자리에 꼭 세 판을 채울 필요는 없다. 한 조 리허설에서는 원하는 시점에 아래 이동 절차도 시험해볼 수 있다.

1. 총괄 GM이 **조 이동 준비 요청**을 누른다.
2. 현재 판과 공개 후 대화를 마친다. 요청 이후 새 판 시작은 잠시 막힌다.
3. 조 리모컨에서 **대화 마침 · 이동 준비 완료**를 누른다.
4. 총괄 관제에서 **새 조 공개 · 이동 시작**을 누른다.
5. 한 조이므로 같은 자리에 머물며 **준비 완료 · Game 시작**으로 다음 판을 연다.

3조 행사에서는 각 조 GM이 독립적으로 진행하고, 전 조가 준비되어야 총괄이 새 조를 공개한다. 기본 구성에서는 학생 3명씩 이동하고 GM은 자기 조에 남는다. 총괄의 타조 관제는 일시정지·재개·강제 공개 같은 복구에 사용한다. 각 조의 평소 단서·추리 진행은 그 조 GM의 리모컨으로 한다.

마칠 때는 총괄 GM이 **전체 종료**를 확인해 실행한다. 종료된 행사를 처음부터 다시 시작하려면 새 리허설을 준비한다. 기존 기록을 즉석에서 지우지 않는다.

## 6. 짧은 리허설 확인표

- 4명 또는 6명이 모두 자신의 프로필을 제출하고 후보에 포함됐다.
- 참가자가 직접 다음 단서를 넘길 수 없고 GM이 대화 뒤 전달했다.
- GM이 추리를 열기 전에는 제출할 수 없고, 연 뒤에는 현재 담당자만 제출했다.
- GM을 포함한 참석자 전원이 투표했고 리모컨에서 투표 화면으로 돌아올 수 있었다.
- 오답·투표·공개 후 새로고침해도 상태와 대기 이유를 이해할 수 있었다.
- 질문 원문과 답이 보였고 Noise 선택지는 내용이 있는 세로 목록이었다.
- 다음 판 최대 Noise 설정과 조기 정답이 이해됐고, 이동 준비·확정·전체 종료를 진행했다.
- 후보에서 제외된 사람도 자기 선택을 이야기했고, 참가자끼리 후속 질문이 나왔다.

기능 검사가 통과한 것과 재미·대화량이 좋아진 것은 별개다. 사람이 직접 사용한 뒤 무엇이 대화를 끊었는지, GM이 어떤 버튼에서 헷갈렸는지 기록한다. 자동화·브라우저 에뮬레이션만으로 실물 휴대폰과 행사 Wi-Fi까지 확인했다고 보지 않는다.

화면만 미리 볼 때는 별도로 안내된 **화면 둘러보기** 링크를 사용한다. GM 예시 6개는 합성 상태를 보여주며 실제 참가 등록·DB 게임 진행과 연결되지 않는다. 기존 감독 리허설의 역할 전환·데모 응답 기능과 구분한다.

최신 구현·자동 검증·배포 범위는 [GM 운영 안내의 검증 기록](gm-mode.md#9-구현검증-기록)에 있다.
