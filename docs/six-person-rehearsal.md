# 6명이 직접 참여하는 리허설

호스트 1명과 참가자 5명이 한 조로 실제 게임에 참여한다. 각자 자신의 휴대폰이나 브라우저에서 같은 `/e/<slug>` 주소로 접속한다. 한 사람이 역할을 바꾸는 `/rehearsal/<slug>` 감독 도구와 별개의 행사다.

## 입장과 시작

1. 담당자가 다섯 사람에게 **학생01~학생05**를 하나씩 정해준다. 이름은 테스트용 자리 표시이며 실제 직책과 관계없다.
2. 다섯 참가자는 자기 이름을 선택한다. 호스트는 **운영진A**를 선택하고 별도로 전달받은 코드를 입력한다.
3. 호스트를 포함한 여섯 명이 각각 A/B 20문항에 답하고 프로필을 제출한다.
4. 호스트는 화면 위 **관리자 → 진행**에서 **조 편성 → 조 배정 공개 → Game 1 전체 시작**을 누른다. 참가자 목록의 프로필 완료와 A조 6명을 확인한다.
5. 단서를 받은 사람이 내용을 말로 공유한다. 현재 Turn Lead가 다음 Data나 추리를 누른다. 호스트도 단서 수신·정답 후보·투표에 참여한다.

튜토리얼은 자동으로 넘어가지 않는다. **이전·다음**으로 내용을 확인하고, 입장 후에는 화면 아래 **게임 방법 다시 보기**로 다시 열 수 있다. 프로필 화면은 카테고리 표시 없이 질문 A/B만 제공한다. Noise 선택창에서는 팀에 나온 단서의 질문·표시 답변을 세로로 모두 확인하며 고른다.

현재 기기 하나에는 참가자 한 명이 연결된다. 같은 브라우저의 여러 탭은 같은 세션을 공유하므로 여섯 사람이 한 브라우저의 탭만 나누어 사용하지 않는다. 새로고침해도 기존 세션과 답변은 복원된다. 기기를 바꿔 이름이 잠겼다면 호스트의 참가자 관리에서 해당 이름을 잠금 해제한다.

## 게임과 운영

- 기본 규칙은 기존 행사와 같다. Game 1은 Noise가 없고, 이후에는 해당 게임의 Noise·Ensemble·Ground Truth 규칙을 사용한다.
- 6명 기준 기본 Ensemble 시작점은 Data 3이다. 여섯 명 모두 자기 화면에서 투표한다.
- 3블록 × 3게임, 최대 9게임이다. 시간만으로 블록이 자동 이동하지 않는다.
- 정답 공개 뒤 호스트가 **다음 Game 시작**을 누른다.
- Game 3·6을 마치면 호스트가 **다음 블록 시작**, 이어 **준비 완료 · Game 시작**을 누른다. 한 조이므로 참가자와 자리는 유지된다.
- Game 9 뒤 마지막 대화를 나누고 호스트가 **전체 종료**한다.
- 진행을 빠르게 넘길 때는 관리자에서 **현재 Game 종료**를 사용할 수 있다. 실제 추리 검증에서는 참가자의 추리하기를 사용한다.

로그인 보호가 해제된 Preview 링크는 Vercel 계정 없이 열 수 있다. 앱의 호스트 인증은 유지된다. 실제 행사 URL과 코드는 공개 저장소에 저장하지 않는다.

## 새 환경에 준비하기

개발 endpoint와 DB marker를 확인한 환경에서 다음과 같이 생성한다.

```text
# 템플릿을 저장소 루트의 roster-six-person.local.json으로 복사한다.
node scripts/seed-event.mjs --roster roster-six-person.local.json --slug dev-six-person-<고유값> --synthetic
node scripts/issue-operator-codes.mjs --slug dev-six-person-<고유값> --name 운영진A --synthetic
```

템플릿은 `templates/roster-six-person.example.json`이다. 프로필은 미리 채우지 않는다. 코드는 지정한 담당자만 수령하고 공개 문서·채팅·CI 로그에 기록하지 않는다. 기존 slug를 삭제해 재사용하지 않고 새 행사를 만든다. 21명 감독용 초기화 명령을 이 행사에 사용하지 않는다.

한 조 설정은 `teamCount=1`, `moveCountPerTeam=0`, 조 운영진 1명을 요구한다. 여러 운영진을 가진 한 조나 게임에 참여하지 않는 전담 호스트는 이번 지원 범위에 포함하지 않는다. 자동 검증과 실제 여섯 기기 현장 검증은 구분한다.
