# 접속과 DB 사용량 문제

## Preview가 로그인 화면으로 이동하는 경우

일반 요청이 Vercel SSO로 302 이동하면 배포 접근 보호의 영향이다. 배포 Ready 여부와 앱의 오류를 구분한다. 프로젝트에 접근 권한이 있는 계정으로 로그인하거나, 행사 담당자가 정한 Preview 공유 정책을 사용한다. 연결 토큰을 저장소에 올리지 않고 보호 해제를 무조건적인 설치 절차로 만들지 않는다.

## Health가 503인 경우

`/api/health`의 `database: unavailable`은 DB 접속 실패다. 배포 환경변수 범위, 네트워크, DB 상태, 서비스 사용량을 순서대로 확인한다. 드라이버 원문에 연결 정보가 있을 수 있으므로 로그에 그대로 출력하지 않는다.

Neon의 프로젝트 월간 전송량을 초과하면 compute가 중지될 수 있다. Free의 공개 네트워크 전송 한도와 초과 동작은 [Neon 공식 요금제 문서](https://neon.com/docs/introduction/plans#public-network-transfer)를 확인한다. 조회 당시 Free는 프로젝트당 월 5GB였으며, 현재 계정의 적용 조건과 갱신 시점은 콘솔에서 확인한다. quota 초과는 짧은 재시도로 해결되지 않는다. 요금제 변경은 운영자가 비용을 확인한 뒤 진행한다.

## 리허설과 전송량

현재 `src/server/db/snapshot.ts`는 상태를 조립할 때 행사 전체 관련 레코드를 조회한다. 브라우저에 반환하는 DTO가 작아도 DB에서 서버로 오는 전송량은 클 수 있다. 21명 리허설은 가상 참가자를 반복 조회하므로 장시간 켜두지 않는다. 개발 연습을 마치면 프로세스를 종료한다.

개선 우선순위는 다음과 같다. 아직 구현된 기능으로 간주하지 않는다.

1. 로컬 PostgreSQL로 리허설·부하 테스트를 실행하는 별도 환경.
2. 버전만 먼저 확인하고 변화가 있을 때 필요한 참가자·조·게임 범위 조회.
3. 가상 행동을 끈 경우 불필요한 참가자 조회를 생략하고 종료·대기 상태의 조회 빈도 낮추기.
4. 21명 1시간과 확대 인원의 DB 전송량을 측정해 행사 사용량 예산 설정.

조회 최적화에도 정답 비공개, Data 수신자 구분, 버전 충돌, 접속 상태 표시를 유지해야 한다. 캐시를 추가한다면 참가자·행사 경계를 검증해야 하며 비공개 원본 snapshot을 브라우저 캐시로 보내지 않는다.

DB가 중단된 동안 UI만 검토할 때는 develop의 로컬 `/design-preview`를 사용할 수 있다. 합성 데이터와 실제 화면 컴포넌트를 사용하며 DB/API 게임 검증을 대신하지 않는다.
