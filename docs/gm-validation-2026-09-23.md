# GM 개선 검증 기록 · 2026-09-23

GM이 조별로 대화의 속도를 조절하는 모드를 `develop`에 추가했다. 새 행사 설정의 `gameplayMode: "gm"`으로 활성화한다. 기존 classic 행사·기존 Production·main은 유지했다. 질문 20개와 후속 질문도 바꾸지 않았다.

## 구현

- 조 GM의 다음 단서 직접 전달, 추리 열기·닫기, Ensemble 공유 완료·투표·토론 진행.
- 새 단서·오답·진행권 변경 시 추리 허가를 닫고 서버에서 재검증.
- 다음 판 Noise 최대 0~5, Ground Truth 선택. 첫 판은 Noise 0/GT 없음. 예정된 Noise가 모두 나오기 전에도 정답 인정.
- 판 번호와 자리 회차 분리. 이동 요청 후 새 판 시작 차단, 모든 조 준비 완료 후 총괄이 새 배정 공개.
- 공개 전 선택 진단 로그 제거, 행사별 세션 쿠키, 공유 중 진행권 이관 차단, 새로고침 뒤 오답 안내 복원.
- GM의 프로필·출석을 확인해 담당 GM이 참여하지 못하는 판의 시작 방지.
- 최신 GM 화면 6개를 포함한 합성 화면 39개. GM 투표 화면 복귀 버튼, 수동 튜토리얼 유지.

## 검증 범위

| 검증 | 확인 범위 | 결과 |
| --- | --- | --- |
| 기본 검사 | lint, typecheck, 20문항 콘텐츠 원문 일치, build | 통과 |
| 단위 검사 | 권한·규칙·DTO·UI·행사 쿠키 | 최종 개수 기록 예정 |
| 개발 DB 관련 검사 | GM 4명/6명, 10판, 20단서 소진, 12명 3조의 서로 다른 진행 속도·4회차 이동, 세션·DTO·기존 리허설 | 1차 6파일 17개 통과. 최종 전체 결과 기록 예정 |
| 원격 HTTP | 새 합성 4인 행사, 등록부터 2회의 실제 30초 투표·정답·이동·종료 | 255요청, 반복 assertion 449개 통과, 5xx/네트워크 실패 0 |
| 브라우저 UI | 360×640에서 GM 리모컨·추리 개방·다음 판 설정, 튜토리얼 다음/이전 | 가로 넘침·콘솔 오류 없이 확인 |
| 실제 사람·실물 휴대폰 | 현장 대화량, 재미, Wi-Fi, 기기별 동작 | 아직 검증하지 않음 |

원격 HTTP의 두 정답 제출은 검사 전용 합성 행사의 DB 정답을 사용하는 오라클 방식이다. 자연 추리를 검증한 결과가 아니다. 세 번째 판은 이동 확인을 위한 GM 공개, 네 번째 판은 전체 종료로 마쳤다. 검사 행사는 종료했고 해당 세션·코드를 폐기했다. [원격 검사 상세](../scripts/audit/gm-remote/RESULT-2026-09-23.md).

GM 다조 통합 검사는 **학생 9명+GM 3명, 조당 1명 이동** 구성이다. 학생 18명+GM 3명, 조당 3명 이동을 실제 기기에서 확인했다고 해석하지 않는다. 기존 21명 classic 회귀도 GM 21명 검증을 대신하지 않는다.

## 배포와 남은 확인

최종 Preview와 소스 commit은 완료 후 기록한다. 개발 DB에는 `003_gm_progression.sql`을 적용했다. 기존 제약의 범위를 넓히고 기본값이 있는 상태 필드를 추가했으며 기존 migration은 변경하지 않았다.

1차 Preview는 READY이고 `/api/health`가 앱·DB 정상, 인증 없는 행사 페이지 요청이 HTTP 200이었다. Vercel의 별도 `Neon branching` 연동 check는 실패로 남아 있다. 실제 빌드와 지정 개발 DB 접속은 성공했으며, check 실패의 상세 원인은 API 결과에 없었다. 이 기록을 모든 Vercel 연동 검사가 성공했다는 주장으로 사용하지 않는다.

이력이 늘수록 snapshot 조회 크기가 커지는 기존 구조는 유지된다. 이번 작업은 장시간 대규모 부하·DB 월간 전송 한도를 검증하거나 개선한 작업이 아니다. 실제 매니저 리허설에서 후보에서 제외된 사람도 대화에 참여하는지 별도로 평가해야 한다.
