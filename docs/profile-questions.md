# KANT Mingling 프로필 20문항

프로필 및 카드 콘텐츠의 기준 문서입니다. §2·§4 원문은 콘텐츠 검증 스크립트와 비교합니다. 동작 구조는 [기술 개요](architecture.md)를 참고하세요.

## 1. 형식 (원전 규칙)

- 모든 문항은 A/B 중 **하나만** 고른다. '둘 다', '모르겠다', 자유서술, 패스는 없다.
- 20개 모두 답해야 등록이 완료된다. 운영진도 같은 20문항에 답한다.
- 질문 구성(원문): 개인 취향 10개 + 일상/추석 5개 + 웃긴 밸런스 5개. "정답이 있는 질문보다 선택 이유를 서로 물어봤을 때 이야기가 이어지는 질문을 우선한다."
- 민감한 개인정보, 가족관계, 경제상황, 연애, 정치, 종교, 학습 수준을 평가하는 질문은 제외한다(원문).
- 응답으로 성향 유형·점수·태그를 만들지 않는다(F20).

## 3. Data 카드와 Noise 표현 (D)

- **실제 Data 카드:** Data Owner가 고른 선택지 문장을 그대로 크게 보여준다. 예: "Data 03 · 민트 초코는 맛있다"
- **Noise 카드:** 같은 문항에서 Owner가 고르지 **않은** 쪽 문장을 보여준다. 실제 카드와 모양이 같다.
- 문항은 A/B 둘뿐이므로 Noise는 항상 '반대 답'이다. 한 GAME에서 한 문항은 실제든 Noise든 한 번만 쓴다.
- 정답 화면에서는 모든 카드에 Real / Noise / Ground Truth를 표시한다. Noise 카드 옆에는 Owner의 실제 답도 함께 보여 준다(D, 가짜 정보가 사실처럼 남지 않게).

## 4. Behind the Data 질문 초안 (D)

원문은 "실제 DATA 중 대화하기 좋은 질문 1개를 시스템이 추천"하고 Data Owner가 15~30초 이야기한다고 정했다. 원문 예시는 "민수님은 여행을 즉흥적으로 가는 편이라고 했어요. 실제 여행 스타일은 어떤가요?"이다.

- 화면 형식: 첫 줄은 "{이름}님의 선택: ‘{선택 문장}’"(받침에 따라 조사가 틀리지 않게 조사를 붙이지 않는다). 다음 줄에 아래 질문을 붙인다.
- 질문은 A/B 어느 쪽을 골랐든 쓸 수 있게 만들었다. 승완 님 검토 전의 초안이다.

## 5. 콘텐츠 카탈로그 스키마 (구현용)

```json

  "contentVersion": "2026-09-22.1",
  "questions": [
    {
      "id": "Q01",
      "category": "개인 취향",
      "options": { "A": "마라수혈은 필수다", "B": "마라탕은 내 입맛에 맞지 않는다." },
      "followUp": "마라탕에 대한 솔직한 생각, 한 줄로 말해 준다면?"
    }
  ]

```

- 20개 문항, ID 중복 없음, 선택지는 정확히 A·B 두 개. 콘텐츠 검사 스크립트로 확인한다.
- 성향 축·유형·점수 필드는 두지 않는다.

## 6. 다른 행사에 적용하기 전 검토할 사항

기준 버전의 문항은 그대로 보존한다. 다른 행사에 적용할 때는 담당자가 아래 적합성을 검토한다.

- **Q15:** 조용한 참가자가 많은 행사라, 단서로 공개되면 팀이 평소 인상으로 사람을 지목할 수 있다.
- **Q18·Q20:** 결혼·돈을 다루는 가정형 질문이다. 원문 제외 목록(연애·경제상황)과 겹쳐 보일 수 있는데 패스가 없다.
- **목적과의 관계:** 원문 목적에 '학습·운영 이야기, 10월 팀 프로젝트'가 있지만, 학습·DS 관련 문항은 Q13 하나뿐이다.
- **Q11~Q13:** 추석 직후 행사(10/01)라는 전제의 문항이다. 일정이 바뀌면 다시 봐야 한다.
